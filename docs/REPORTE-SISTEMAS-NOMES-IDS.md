# 🧩 PARTE 1 — SISTEMAS DE IDENTIFICADORES (IDs)

## 1.1 — ID de Projeto (`makeId`)
- **Arquivo:** `src/core/projects/projectsMappers.ts` (líneas 13-15)
- **Fórmula:** `` `${prefix}-${Date.now()}-${Math.random().toString(36).slice(2,10)}` ``
- **Prefixos:** `"local"`, `"sync"`, `"legacy"` (projectsClient/Merge/OfflineStore).
- **Nota:** ID no estable — cambia cada creación; usado al persistir proyectos locales/offline.

## 1.2 — ID de Caixa / Workspace (`createBox`)
- **Arquivo:** `src/context/projectState.ts` (línea 139+, 573+)
- El `box.id` se pasa externamente (viene de `workspaceBox.id`); la caja además lleva `nome`.
- `convertWorkspaceToBox()` mantiene `box.id` como clave primaria estable.

## 1.3 — IDs de Paneles de la Caja (`ensureBoxPanelIds` / `createStableId`)
- **Arquivo:** `src/core/box/panelIds.ts`
- `createStableId()` (línea 4): `` `${Date.now().toString(36)}-${Math.random().toString(36).slice(2,11)}` `` — ID tipo UUID-like, no versionable.
- `ensureBoxPanelIds()` genera IDs para: `cima`, `fundo`, `lateral_esquerda`, `lateral_direita`, `costa`, `frente_fixa`, y arrays `prateleiras`, `portas`, `gavetas`, `divisores`, `separadores`.
- **Consumido en:** `useBoxCrudActions.ts`, `useDivSepActions.ts`.

## 1.4 — IDs de Fabricación (hardware/materiales/ferragens)
- **Arquivo:** `src/core/manufacturing/boxManufacturing.ts` (línea 141) — `` `${prefix}-${index+1}` ``
- Usado para `pe_plastico`, `PARAFUSO_3X30`, estructuras etc.
- **Also:** `src/core/cornerCabinet/cornerCabinetManufacturing.ts` (línea 29).

## 1.5 — IDs de Piezas del Industrial Designer (`nextDesignId`)
- **Arquivo:** `src/core/industrialDesigner/designModel.ts` (líneas 21-26)
- Fórmula: `` `${prefix}-${Date.now().toString(36)}-${_idCounter}` `` (contador global).
- ID jerárquico: `box.id:porta`, `box.id:prateleira` (`industrialCornerGeometry.ts`, `industrialBase600x720x500v1.ts`).

## 1.6 — IDs de Capas/Puertas del Viewer (`createId`)
- **Arquivo:** `src/services/boxLayersService.ts` (línea 70) — `createId("door")`.

## 1.7 — IDs de Notificaciones/Export (stores locales)
- `src/stores/industrialExportPanelStore.ts` — `makeId()`
- `src/stores/invariantNotificationStore.ts` — `makeId()`

## 1.8 — IDs de Materiales (`generateId`)
- **Arquivo:** `src/core/materials/service.ts` (línea 190).

# 🧩 PARTE 2 — SISTEMAS DE NOMES (NAMING)

## 2.1 — Nome automático de Projeto (NP…)
- **Arquivo:** `src/context/projectState.ts` (línea 108)
- Fórmula: `NP` + ano(2) + dia + mes + hora (sin ceros izq.), ej.: `2026-04-01 10:15 → NP261410`.
- **Unicidad:** `ensureUniqueAutoProjectName()` (línea 119) agrega 2 chars hasta libre.
- **Reconocimiento:** `isLikelyAutoGeneratedProjectName()` en `cutLayoutProPieceNaming.ts` (línea 51).

## 2.2 — Nome Industrial da Peça (etiqueta/PRO)
- **Arquivo:** `src/core/cutlayout/cutLayoutProPieceNaming.ts`
- **Estructura:** `<prefixoCaixa>_<prefixoPeca>` y nombre completo `{projeto}_{caixa}_{peca}` (`industrialDisplayName.ts:buildV5BottomStripIndustrialName`).
- **Prefixos pieza** (`TIPO_TO_PREFIX` / `NOME_PT_TO_PREFIX`):
  `lateral_direita → lat_dir`, `lateral_esquerda → lat_esq`, `gaveta_frente → gav_frent`, `gaveta_fundo → gav_fun`, `cima → top`, `fundo → fun`, `COSTA → cos`, `prateleira → pra`, `porta_simples → por_sim`, `porta_dupla → por_dup`, `porta_correr → por_cor`, `remate → rem`, `rodape → rod_pe`.
- **Prefijo caja** (`buildBoxPrefixForCutLayoutPro`, línea 82): 1ª palabra + último número del display (`C1`), o NP, o inicial custom.

## 2.3 — Nome peça en cutlist / Layout PRO
- `buildCutLayoutProPartName()` (línea 112) — boxPrefix + piecePrefix.
- `cutlistItemsWithCutLayoutProNames()` (línea 192) — usa `metadata.industrialLabel` si existe, sino PRO name.
- `buildBoxNomeByIdFromBoxes()` (línea 213) — mapa boxId→nome.

## 2.4 — Inversión L/R (lados del módulo)
- `invertModuleLateralTipoForIndustrialLabel()` (línea 129) y `applyIndustrialLabelSideInversion()` (línea 139).
- **NOTA:** en PDF etiqueta/TCN/REF los lados se invierten (`lateral_dire_ → lat_esq`), mientras Viewer/cutlist mantienen SSOT — **fuente clásica de divergencia**.

# 🧩 PARTE 5 — OS "PORÉM" / PONTOS DE DIVERGÊNCIA

O utilizador observou que, apesar de várias tentativas de unificação, **ainda há lugares que geram nomes/IDs distintos**. Pontos de divergência identificados:

| # | Divergência | Sistemas envolvidos | Causa |
|---|---|---|---|
| 1 | **ID caixa vs slug caixa** | `box.id` (UUID random) vs `toProjetosBoxSlug` (slug do nome) | Chaves paralelas ligadas só por Mapas; reprocessamento pode quebrar o vínculo |
| 2 | **Nome SSOT vs nome etiqueta** | `cutLayoutProPieceNaming` (sem inversão) vs `buildIndustrialPieceName` (com inversão L/R) | Inversão apenas em etiquetas/REF gera nomes diferentes |
| 3 | **Nomes PT vs prefixos técnicos** | `TIPO_TO_PREFIX`/`NOME_PT_TO_PREFIX` vs `industrialLabel` (manual) | `industrialLabel` sobrepõe o automático quando existe |
| 4 | **Três geradores de ID random** | `makeId()`, `createStableId()`, `nextDesignId()` | Cada um com formato próprio; sem padrão único |
| 5 | **`buildId(prefix,index)` manual** | `boxManufacturing` vs `cornerCabinetManufacturing` | Mesma lógica duplicada; índices podem colidir |
| 6 | **NP (auto) vs custom prefix** | `formatAutoProjectName` vs `prefixFromCustomProjectName` | Prefijo caja muda estratégia consoante o nome do projeto |
| 7 | **Page slug normalize** | `toProjetosPageSlug` vs `decodeProjetosPageSlug` | Comparação URL depende de normalização cuidadosa |
| 8 | **IDs de painéis por posição vs UUID** | `getStructuralPanelId`/`getArrayPanelId` vs `ensureBoxPanelIds` | Dois regimes: index vs UUID consoante existência de panelIds |

# ✅ CONCLUSÃO

Existe **1 orquestrador unificador** (LabelSystemV5/UEE para etiquetas), mas **diversos geradores de ID/name independentes** ainda não convergem num padrão único:

- **IDs:** ≥5 geradores distintos (`makeId`, `createStableId`, `nextDesignId`, `buildId`, `generateId`, `createId`).
- **Nomes:** ≥3 camadas (`projectState` NP, `cutLayoutProPieceNaming` PRO, `industrialDisplayName` etiqueta).
- **Códigos/QR:** 1 sistema centralizado v5 (LabelSystemV5 + etiquetaCodeV5) — o mais consolidado.
- **Slugs URL:** 2 ficheiros distintos (pageSlug + focusSlug) ligados por Mapas.

### 🛠️ Recomendações (para futura unificação — NÃO aplicadas)
1. Centralizar num único gerador de ID (ex.: `createStableId` global com prefixo por entidade).
2. Usar `cutLayoutProPieceNaming` como **única** fonte de nomes industriais, eliminando a inversão duplicada.
3. Unificar os Mapas box/piece slug no estado global (evitar reconstrução perde vínculos).
4. Documentar `industrialLabel` como override explícito.
